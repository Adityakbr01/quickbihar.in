## Problem
No daily scheduler exists for SEO automation. The `seo-policy.yaml` defines a daily workflow but no GitHub Actions cron, system cron, or OpenSEO MVP scheduler is configured. Without scheduling, automation cannot run daily as designed.

## Supporting Evidence
- **Source:** `seo-automation/config/seo-policy.yaml` — assumes daily execution
- **Source:** `.github/workflows/` — only `docker-ci-cd.yml` exists (deploys on push to master/main)
- **Source:** No OpenSEO MVP scheduler config found in repo
- **Source:** Historical 2026-10-16 report — "Scheduler status: NOT CONFIGURED"
- **Retrieval timestamp:** 2026-10-19

## Proposed Change
Option A: GitHub Actions cron (recommended, uses existing CI)
- Create `.github/workflows/seo-daily.yml` with `on: schedule: - cron: '0 2 * * *'` (2 AM UTC = 7:30 AM IST)
- Job: checkout, setup Node, install deps, run SEO audit script, commit report/proposals
- Use `seo-automation/config/seo-policy.yaml` for config

Option B: OpenSEO MVP scheduler (if available)
- Inspect OpenSEO MVP for built-in scheduler
- Configure per its documentation

Option C: VPS system cron (self-hosted runner)
- Add cron entry on VPS to run audit script daily

**Recommendation**: Start with Option A (GitHub Actions) — uses existing infrastructure, no new servers, logs in Actions tab.

## SEO/User Rationale
Daily automation enables:
- Continuous monitoring of technical SEO health
- Early detection of regressions (404s, noindex, canonical breaks)
- Trend tracking of search performance
- Timely proposals for review

## Expected Benefit

- Proactive issue detection
- Historical trend data for analysis
