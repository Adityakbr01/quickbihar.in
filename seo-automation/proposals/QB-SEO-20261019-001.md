## Problem
The route `/clothing/home` is defined in `STATIC_ROUTES` (routes.ts line 20) but is NOT included in `sitemap-static.xml`. It duplicates the root `/` homepage content. Historical GSC data (2026-10-14) showed "Duplicate without user-selected canonical" for 4 pages, likely including this duplication. The current prerender shell correctly links "Home" to `/` (not `/clothing/home`), but the route remains in STATIC_ROUTES and could be crawled/indexed separately.

## Supporting Evidence
- **Source:** `user-web/src/seo/routes.ts` line 20 — `{ path: '/clothing/home', label: 'Home' }` in STATIC_ROUTES
- **Source:** Live `sitemap-static.xml` — only 6 URLs, `/clothing/home` absent
- **Source:** Historical GSC coverage (2026-10-14) — "Duplicate without user-selected canonical: 4"
- **Retrieval timestamp:** 2026-10-19
- **Reproduction:** Check STATIC_ROUTES array vs sitemap-static.xml output

## Proposed Change
Remove `/clothing/home` from `STATIC_ROUTES` in `user-web/src/seo/routes.ts`. The root `/` already serves as the canonical homepage (both `/` and `/clothing/home` currently render the same content per SeoRouter.tsx lines 324-338 which consolidate both to root canonical).

## SEO/User Rationale
Eliminates duplicate content risk, consolidates link equity to single canonical homepage, resolves historical GSC duplicate canonical warning. Users already navigate to `/` via shell links.

## Expected Benefit
- Removes duplicate canonical issue from GSC
- Consolidates organic impressions/clicks to single URL
- Cleaner route inventory for crawl budget

## Risk Assessment

- **Dependencies**: None — SeoRouter already handles both paths with same canonical
- **Regression**: None expected
